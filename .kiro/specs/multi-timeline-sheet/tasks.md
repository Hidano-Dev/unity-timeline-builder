# Implementation Plan

- [ ] 1. モデル基盤の整備
- [ ] 1.1 (P) グループ化済み構築計画の不変モデルを追加する
  - 1 つの Timeline グループ分の構築計画（CSV 記載の Timeline 名・グループ初出行番号・帰属するクリップ行・Scene 構築計画）を保持する不変モデルを新設する
  - レガシー単一グループ（Timeline 名なし）を表現できるようにし、既存のクリップ行・Scene 計画の型は無変更で内包する
  - コンストラクタで入力コレクションをコピーし、生成後に状態が変化しないことをコンパイルと簡易テストで確認できる状態にする
  - _Requirements: 1.2, 1.3, 2.4_
  - _Boundary: TimelineGroupPlan_

- [ ] 1.2 (P) 構築結果モデルを複数出力対応へ加法的に拡張する
  - グループ別成果物（Timeline 名・確定アセット名・TimelineAsset / Prefab / Scene の各パス・Scene 計画有無）を表す公開モデルを新設する
  - 構築結果へグループ初出順の成果物一覧を追加し、既存の単一値プロパティは一覧の先頭要素へ写像する規則を実装する
  - 既存の公開コンストラクタ 2 種を維持し、引数から単一成果物を合成する規則（アセット名の導出・Scene 計画有無の判定・全パス null 時は一覧を空にする）を実装する
  - エラーモデルへ対象 Timeline 名（nullable）を加法的に追加し、既存コンストラクタでは null になることを保証する。エラーコード列挙体の末尾へ AssetName 競合を追加し既存値の序数を変えない
  - レガシーコンストラクタの合成規則・先頭グループ写像・Timeline 名の既定 null を単体テストで検証し、既存のモデルテストが引き続き成功する
  - _Requirements: 4.1, 4.4, 5.1, 6.3_
  - _Boundary: BuildResult, BuildOutput, BuildError_

- [ ] 2. パーサーの複数 Timeline グループ化対応
- [ ] 2.1 timeline カラム認識と行のグループ帰属を実装する
  - ヘッダー行がある場合にのみ timeline カラムを認識する（列名照合は既存ヘッダーと同じ大文字小文字非区別・列順自由）。ヘッダーレスシートは従来の既定 7 列順・単一グループとして解釈する
  - 各データ行（クリップ行および Scene / ScenePrefab / SceneBind 行）を timeline セルの値から帰属グループへ割り当て、同一 Timeline 名（トリム後の Ordinal 完全一致）の行を行の連続性に関係なく同一グループへ集約する
  - パース結果をグループ列ベース（初出順）へ再構成し、timeline カラムの認識有無を後段の競合検査で参照できるようにする。timeline カラムが無い場合は全行を Timeline 名 null の単一グループへ集約する
  - 既存の行検証（必須列・数値・範囲・trackType 判定）と RFC 4180 / ヘッダー判定 / 7 列フォールバックの規約は無変更で再利用する
  - インターリーブした行を含むシートが初出順のグループ列としてパースされることを確認できる状態にする（既存テストの追従とテスト拡張は 2.4 で実施。ビルドパイプライン側の追従は Task 4 で実施）
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.6, 6.2_
  - _Depends: 1.1_

- [x] 2.2 timeline セル必須検証と Timeline 名の妥当性検証を実装する
  - timeline カラムが存在する場合、全データ行で timeline セルの値を必須とし、空欄は行番号付きエラーとして報告する
  - Scene 名の既存検証ロジックをファイル名妥当性の共通ヘルパーへ抽出し、Timeline 名にも同一規則（制御文字・禁止文字・末尾ピリオド/空白・予約名の拒否）を適用する
  - 違反時は行番号と対象の名前を特定できるエラーを全行分集約してから返し、構築処理が中断されることを確認できる状態にする
  - _Requirements: 1.5_

- [x] 2.3 Scene 関連行の検証をグループ単位へ再スコープする
  - Scene 行の 1 行制約をシート全体からグループ単位（グループごとに高々 1 行）へ緩和し、グループ内で 2 行以上あれば行番号付きエラーにする
  - Scene 行を持たないグループに ScenePrefab / SceneBind 行が存在する場合を行番号付きエラーにする
  - SceneBind の Track 名重複検証をグループ内スコープへ変更し、別グループ間では重複を許容する
  - 2 グループがそれぞれ Scene 行を 1 行ずつ持つシートがエラーなくパースされることを確認できる状態にする
  - _Requirements: 3.1, 3.4, 3.5, 3.6_

- [x] 2.4 パーサー単体テストをグループ前提へ更新・拡張する
  - 既存のパーサーテストをグループ列ベースのパース結果へ追従させ、全件成功させる
  - timeline カラム認識（列順自由・ヘッダーレス無視・列名の大文字小文字）、インターリーブ行の初出順グループ化、空欄・不正名エラーの行番号、グループ単位の Scene 行制約（超過・前提欠落・SceneBind 重複のスコープ）、レガシー入力の単一グループ化をテストで網羅する
  - EditMode テストランナーで追加・更新した全テストが成功する
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 1.6, 3.1, 3.5, 3.6, 6.2_

- [ ] 3. 出力パスの計画と衝突解決
- [x] 3.1 (P) 命名確定・衝突検出・連番サフィックス付加の純ロジックを実装する
  - グループのアセット名を Timeline 名（トリム済み）から確定し、レガシー単一グループでは従来規則（AssetName 引数またはシートファイル名）のフォールバック名を使用する
  - 同一ビルド内の計画出力パス間のみを対象に、大文字小文字非区別で衝突を判定する（ディスク上の既存アセットは対象外）。衝突単位はアセット名（.playable / .prefab のペアで常に同名維持）と Scene 名の 2 種類とする
  - グループ初出順に処理し、先出が名前を保持、後出へ ` (1)` から始まる連番サフィックスを衝突が消えるまで増分して付加する。リネームごとに元の名前と最終パスを特定できる警告メッセージを生成する
  - Unity API に依存しない純ロジックとして実装し、返却される全パスが互いに一意・入力順序保持であることを保証する
  - 衝突を含むグループ列を入力すると、サフィックス解決済みの出力パス計画と警告一覧が得られることを確認できる状態にする
  - _Requirements: 2.3, 2.5, 3.7_
  - _Boundary: OutputPathPlanner_
  - _Depends: 1.1_

- [ ] 3.2 出力パス計画の単体テストを作成する
  - 大文字小文字違いのアセット名衝突とサフィックス付加・警告生成、Scene 名同士の衝突、サフィックス自体の再衝突（元名とサフィックス付き名が両方 CSV に存在するケース）を網羅する
  - .playable / .prefab ペアの同名維持、レガシーフォールバック命名、先出グループの名前保持、Scene 名 = Timeline 名でも同一グループ内衝突が発生しないことを検証する
  - EditMode テストランナーで全テストが成功する
  - _Requirements: 2.3, 2.5, 3.7_

- [ ] 4. ビルドパイプラインの再構成
- [ ] 4.1 Scene 保存確認ダイアログの責務を Scene 生成コンポーネントから除去する
  - Scene 生成処理の冒頭にある保存確認ダイアログ呼び出しを削除し、ダイアログ責務をパイプライン統括側（4.3 で実装）へ移す前提を整える
  - Scene 生成・配置・バインド・保存のその他の契約は不変に保つ
  - 該当ケースの既存テストを特定し、パイプライン側テストへの移設対象として整理した上で、残りの Scene 生成テストが成功する
  - _Requirements: 3.2_

- [ ] 4.2 検証ステージ（競合検査とエラー全件集約）を実装する
  - パース後、timeline カラムを認識したシートに AssetName（API 引数）が指定されている場合は AssetName 競合エラーで生成前に中断する
  - 出力パス計画を確定した後、全グループのリソース解決と Scene 検証（Scene 計画を持つ全グループへグループの行・計画済みパスで実施）をすべて実行してからエラーを合算し、1 件以上あればアセットを生成せず失敗を返す（現行の早期 return を廃止）
  - 各検証エラーへ帰属グループの Timeline 名を設定する
  - 複数グループにまたがる検証エラーが 1 回の実行でまとめて報告され、アセットが一切生成されないことを確認できる状態にする
  - 公開 API のシグネチャ（Build 2 種・BuildRequest）は不変に保つ
  - _Requirements: 4.2, 4.4, 5.4, 5.5_

- [ ] 4.3 生成ステージ（グループ逐次生成・fail-fast・結果組み立て）を実装する
  - リネーム警告を生成前に既存の接頭辞付きログで出力し、グループ初出順に Timeline → Prefab → Scene を逐次生成する。各 Factory へはそのグループの行・計画済みパスのみを渡し、トラック集約をグループ内に限定する
  - Prefab ルート名・Scene の Director オブジェクト名にはサフィックス適用後の確定アセット名を使用し、Scene の暗黙参照は同一グループの計画済み TimelineAsset パスで解決する。アセット保存・同期 Import はグループごとに実行する
  - 非バッチ時は最初の Scene 生成の直前に保存確認ダイアログを 1 回だけ実行し、キャンセルは既存のキャンセルエラーコードで fail-fast する
  - 生成失敗時はその時点で中断し、失敗エラーへ Timeline 名を付与、生成済み成果物はディスクへ残し、成果物一覧には生成が完了したパスのみを設定する
  - 既存アセットへの上書きログと成果物ごとの既存ログ書式を維持し、レガシー入力（timeline カラムなし）では従来と同一の命名・出力先・ログ・結果になる
  - 複数グループのシートを 1 回のビルドで実行すると全グループの TimelineAsset / Prefab / Scene が生成され、成果物一覧が初出順で返却されることを確認できる状態にする
  - _Requirements: 2.1, 2.2, 2.4, 2.6, 3.2, 3.3, 4.1, 4.3, 6.1_

- [ ] 5. CLI の複数成果物ログと Timeline 名付きエラー報告を実装する
  - 成功時は成果物一覧を走査し、成果物ごとに既存書式でログ出力する（レガシー入力では現行と同一の行数・書式になる）
  - 失敗時のエラー書式へ Timeline 名を `[timeline: ...]` 書式で追記し、Timeline 名が null の場合は現行書式のままとする
  - 引数仕様と exit code 体系（0/1/2）は不変とし、AssetName 競合は exit code 1 のビルドエラーとして報告される
  - 複数グループのシートを CLI 実行すると全成果物パスがログ出力され exit code 0 で終了することを確認できる状態にする
  - _Requirements: 5.2, 5.3, 5.4_

- [x] 6. (P) 複数 Timeline テンプレートの追加と列定義の同期
  - timeline カラム付きヘッダーで 2 グループ以上を記載した同梱テンプレート CSV を新規追加する。各グループにクリップ行を置き、片方に Scene / ScenePrefab / SceneBind 行とインターリーブの例を含める
  - 列定義ドキュメントへ timeline カラムの名称・意味・データ型・必須/任意・認識条件（ヘッダー行必須）・記入例、行の帰属規則（行順自由・初出順出力・Ordinal 同一性）、グループ単位へ緩和された Scene 行制約、アセット名規則と AssetName 競合エラー、衝突時の連番リネームと警告、予約列名としての注意を追記する
  - 既存の単一 Timeline テンプレートは無変更に保ち、テンプレート・ドキュメントの内容が 2.1〜2.3 で実装したパーサー仕様と一致していることを突き合わせで確認できる状態にする
